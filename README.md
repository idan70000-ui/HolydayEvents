שרשרת תהליך האוטומציה שלנו:
GitHub → Jenkins → Build/Test → Docker Image → Docker Hub → Ansible → Deployment Server → Running App



מבנה הפרויקט – מה כל קובץ עושה:

server.js	קוד האפליקציה עצמה (Node.js), כולל endpoint בשם /health שמדווח אם האפליקציה תקינה

package.json	רשימת התלויות (הספריות) שהאפליקציה צריכה כדי לרוץ

Dockerfile	מתאר איך "לארוז" את האפליקציה לתוך Docker Image – איזו גרסת Node.js להשתמש, אילו קבצים להעתיק, איזה פורט לחשוף

docker-compose.yml	קובץ נוח להרצה מקומית של האפליקציה בזמן פיתוח

Jenkinsfile	"מתכון" מלא לכל תהליך ה-CI/CD – מגדיר את כל השלבים ש-Jenkins צריך לבצע, בסדר הנכון

inventory.ini	קובץ שאומר ל-Ansible באיזה שרת יעד להשתמש, ואיך להתחבר אליו (כתובת, פורט, שם משתמש, סיסמה)

setup.yml	Ansible Playbook שמכין את שרת היעד – מתקין עליו Docker אם הוא עוד לא שם

deploy.yml	Ansible Playbook שמבצע את הפריסה בפועל – מוריד את הגרסה החדשה של האפליקציה ומריץ אותה על שרת היעד

Jenkins מריץ את ansible-playbook -i inventory.ini setup.yml, תפקידו הוא להתקין את הסביבה של דוקר על השרת שלנו באנסיבל כולל את כל חבילות הבסיס הנדרשות.





Jenkins מריץ את ansible-playbook -i inventory.ini deploy.yml, אשר:
מושך את האימג העדכני ביותר מדוקר האב
עוצר ומסיר את הקונטיינר הישן, אם קיים
מריץ קונטיינר חדש מהאימג שמשכנו (הכי עדכני)
ממתין מספר שניות לעליית האפליקציה
שולח בקשה ל-endpoint GET /health ומוודא תשובת 200 עם תוכן שמכיל "healthy"
נכשל אם הבדיקה לא עוברת כדי שגנקינס ידע שהדיפלוי שעשינו לא עבד או לא הצליח......




האפליקציה שלנו רצה בצורה טובה ותקינה על השרת בפורט 3001:3000
מכיוון שיש לנו גם קונטיינר מקומי במחשב שלי שיושב על פורט 3000
אנחנו היינו צריכים להגדיר במיפוי החיצוני שלנו מהמחשב לשרת פורט 3001 כי היה עוד קונטיינר על המחשב המקומי שתפס את הפורט הזה
ולכן האפליקצייה עצמה על 3000 תמיד אבל הפורט המקומי שבין השרת אנסיבל שלנו למחשב זה 3001




Pipeline: שלבים של כל הפלואו

Jenkins עוקב כל הזמן אחרי הריפו ב-GitHub (בשיטה שנקראת Poll SCM – הוא בודק כל 2 דקות אם יש שינוי חדש). ברגע שהוא מזהה push חדש, הוא מתחיל build אוטומטי שעובר את השלבים הבאים:
Checkout – Jenkins מוריד לעצמו את הגרסה העדכנית ביותר של הקוד מ-GitHub.
Install Dependencies – מריץ npm install כדי להתקין את כל הספריות שהאפליקציה צריכה.
Test – מריץ את הבדיקות האוטומטיות של הפרויקט, כדי לוודא שהשינוי החדש לא שבר שום דבר.
Build Docker Image – בונה Docker Image חדש מהקוד, לפי ההוראות שכתובות ב-Dockerfile.
Tag Image – נותן ל-Image שם/תווית ברור (עם מספר ה-build), כדי שאפשר יהיה לזהות אותו בעתיד.
Push to Registry – דוחף את ה-Image המוכן ל-Docker Hub, שהוא ה"מחסן" הציבורי שבו שומרים Images מוכנים לשימוש.
Deploy – זה השלב המעניין ביותר: Jenkins לא מריץ את האפליקציה בעצמו, אלא קורא ל-Ansible שיעשה את זה עבורו על שרת אחר (ראו הרחבה למטה).
